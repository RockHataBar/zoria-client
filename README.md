# Зоря.нет — клієнт учасника

Клієнт мережі Зоря.нет, частина 1 «Вихід на зв'язок»: слухає ефір і перевіряє печатку станції,
реєструється в просвіт, показує статус доступу до репозиторію, листи, новини й частини завдання.
React + TypeScript, збирання Vite. Зовнішніх ресурсів (шрифтів, CDN) немає: єдині мережеві запити йдуть до API мережі.

## Вимоги

- Node.js 24 або новіший (скрипт `watch` виконує TypeScript напряму).
- npm (lockfile — `package-lock.json`).

## Встановлення і запуск

```bash
npm ci          # встановлення точно за lockfile
npm run dev     # клієнт на http://localhost:5173
```

Інші команди:

```bash
npm test            # модульні тести (vitest): контрольні кадри A-D, реєстрація, валідація, розмітка
npm run typecheck   # перевірка типів
npm run build       # збирання в dist/
npm run preview     # показ зібраного dist/
npm run watch       # нічна варта в терміналі: слухає ефір і реєструє сам (див. нижче)
```

## Сервер: бойовий або стенд

Адреса сервера — налаштування, код правити не треба:

- у клієнті: вкладка «Налаштування» → «Бойовий сервер» / «Навчальний стенд» / інша адреса API;
- під час збирання або запуску: змінна `VITE_ZORIA_SERVER` = `prod` (за замовчуванням), `stand` або адреса API,
  і за потреби `VITE_ZORIA_FINGERPRINT` — відбиток ключа печатки (64 hex), наприклад у файлі `.env.local`:

```
VITE_ZORIA_SERVER=stand
```

| Сервер | Адреса API | Відбиток ключа печатки |
| --- | --- | --- |
| бойовий | `https://zoria.net/api/v1` | `dcb3155eb8f2538d466a294315e984fa9f67f703556c5e276d5b3afc88895696` (ТЗ, розділ 3) |
| стенд | `https://stand.zoria.net/api/v1` | `d8860c95b821dc56c0f44a2f0b22f3e157af83bfaed9e55206ac5109d4230a1a` |

Для `npm run watch` те саме задають `ZORIA_SERVER` і `ZORIA_FINGERPRINT` або прапорець `--stand`.

## Реєстрація в просвіт

Просвіт починається в заздалегідь не оголошений момент і триває щонайменше 10 годин. Два способи:

1. **Вебклієнт.** Вкладка «Реєстрація»: логін, відображуване ім'я, пароль, код заявки, приватний репозиторій.
   «Заготовити» — клієнт надішле заявку сам за першим кадром `phase: "window"` із правильною печаткою.
   Вкладку треба тримати відкритою; пароль і код за замовчуванням живуть тільки в пам'яті вкладки.
2. **Термінал:** `npm run watch` питає ті самі поля (пароль і код не показуються й не пишуться на диск),
   слухає ефір і реєструє сам. Надійніше за вкладку браузера, яку система може приспати вночі.

Загублену відповідь на реєстрацію клієнт не повторює наосліп: спершу входить тими самими логіном і паролем.

Після реєстрації:

1. Запросіть до репозиторію GitHub-акаунт `zoria-net-bot` (Settings → Collaborators).
2. Покладіть у корінь гілки за замовчуванням файл `.zoria`, перший рядок — ваш логін у мережі.
3. Статус доступу на вкладці «Доступ» стане `verified` за кілька хвилин. Строк — 2026-10-05 21:00.

Репозиторій лишається приватним до кінця конкурсу.

## Як клієнт поводиться з мережею

- `/ether` — не частіше ніж раз на 15 с, `/ether/roll` — не частіше ніж раз на хвилину і тільки на вкладці «Журнал»,
  `/me/summary` — приблизно раз на 15 с після входу; перечитується тільки те, що зсунулося у зведенні.
- Фаза, відлік провісника і уривки листа беруться тільки з кадрів із правильною печаткою Ed25519 над байтами рядка `frame`;
  стан визначає кадр із найбільшим `at`, ехо і затримка його не відкочують. Помилки без печатки до просвіту — шум.
- Ключ печатки береться з `/ether/key` і звіряється із закріпленим відбитком.
- 429: чекаємо `Retry-After`; після `jammed` — жодного запиту до цього сервера до кінця глушіння.
  Збої (5xx без конверта, обрив, тайм-аут) повторюються з експоненційною паузою з повним джитером (до 60 с).
- Токен сесії зберігається в сховищі браузера (окремо для кожного сервера), передається тільки в `Authorization`,
  запити без cookie (`credentials: 'omit'`). На 401 відкривається вхід поверх поточного екрана — введене лишається.
- Тексти новин, листів і частин показуються як підмножина Markdown без виконання HTML; посилання — тільки http/https.
- Час показується в місцевій зоні пристрою з її назвою; сервер працює в UTC, відлік іде за годинником сервера.

Ліміт ефіру — 20 запитів на хвилину на адресу. Вкладки одного браузера домовляються між собою (Web Locks і
BroadcastChannel): ефір слухає одна вкладка, решта отримують її кадри й самі перевіряють печатку; строк глушіння і
пауза 15 с між запитами `/ether` спільні для вкладок і переживають перезавантаження сторінки. Інші браузери, пристрої
за тією самою адресою і `npm run watch` цього не знають — не запускайте їх одночасно з вебклієнтом.

## Бот, штаб і стек здачі

Бот (частина 2) лежить у `bot/`, штаб (частина 3) - у `hq/`, стек здачі (частина 4) - `compose.yaml` у корені.

```bash
cd bot && npm ci && npm run build && cd ..   # бот: bot/dist/main.js
cd hq && npm ci && npm run build && cd ..    # штаб: один самодостатній файл hq/dist/index.html
npm ci                                       # кит у корені
npx zaria-kit preflight                      # передстартовий прогін: збірка, підйом, проба, ручки, штаб
```

Штаб збирається командою `npm run build` у каталозі `hq` (vite, `vite-plugin-singlefile`); каталог збірки
вказано полем `zaria.hq` у `hq/package.json`. Перевірка штабу драйвером приймання - `npx zaria-kit records`
і `npx zaria-kit hq-check` у каталозі `hq`. У стеку штаб - сервіс `hq` з міткою `zaria.hq`, локально на
`http://127.0.0.1:8180`. Докладніше про стек - `STACK.md`, про штаб - `hq/README.md`.

Перед кожним пушем працює хук `.githooks/pre-push`: сканер секретів [gitleaks](https://github.com/gitleaks/gitleaks)
перевіряє коміти, які йдуть на сервер, і зупиняє пуш, якщо щось знайде (вимога P4-06). Увімкнути один раз
після клонування:

```bash
winget install Gitleaks.Gitleaks      # або brew install gitleaks
git config core.hooksPath .githooks
```

Відомі тестові значення, які не є секретами, перелічено в `.gitleaksignore`.

## Будова

```
src/core/        логіка без React, працює і в браузері, і в Node 24
  http.ts        обмін: тайм-аут, будь-яка відповідь без падіння, глушіння, пауза з джитером
  seal.ts        ключ і печатка Ed25519, розбір кадру
  ether.ts       стан ефіру: фаза, провісник, поправка годинника, уривки, журнал
  etherClient.ts слухач ефіру з частотами опитування
  api.ts         маршрути частини 1 і класифікація відповідей
  register.ts    реєстрація з обробкою загубленої відповіді
  validate.ts    перевірка полів і розбір адреси репозиторію
  markdown.ts    безпечна підмножина Markdown
  paging.ts      посторінкове читання списків
src/app/         стан застосунку: сервер і сесія, заготовка заявки, дані акаунта
src/ui/          вкладки
scripts/watch.ts нічна варта для терміналу
tests/           тести; контрольні кадри A-D зі специфікації
```

Секретів у репозиторії немає: `.env.local`, `*.local.json` і файли сесій ігноруються git.
